# P1: Port the live site into the Astro pipeline, pixel for pixel

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Astro build (`npm run build`) writes every page of the live macdio.app site, with the same markup, CSS and behaviour, so the later steps (guide hub, SEO/GEO pages, media, languages, hub badge) land on top of the real design instead of the parked redesign.

**Architecture:** Each live page is kept as a whole HTML file under `src/legacy/<locale>/` (a `git mv` from `old-site/`). At build time `src/site/legacy.mjs` extracts the page-specific parts (title, description, keywords, robots, JSON-LD, `<main>`) and `src/layouts/Legacy.astro` wraps them in the shared shell: the live head (GA4, OG, Twitter, icons, hreflang, `redesign.css`), a server-rendered nav and footer with the exact markup `parts.js` used to inject, the crawler sitelinks, and `parts.js` + `redesign.js`. Links and asset paths in the extracted content are made root-relative and localized per locale. Translators later copy a whole page file into another locale folder; the shell and the link rewriting do the rest.

**Tech Stack:** Astro 7 (`build.format: 'file'`), the live `redesign.css` / `redesign.js` / `parts.js` unchanged except for the nav builders moving server-side, Node test runner.

**Spec:** docs/superpowers/specs/2026-10-12-macdio-web-v2-design.md, superseded on visual design by tracker W10 (keep the live design).

## Global Constraints

- The rendered pages must look and behave like the live site: same `redesign.css`, same class names, same scripts, same section order.
- No em dash, no `---`, no we/our/us for the developer in user-facing text (fix the handful the live site has, list them for Sait).
- Nothing deploys without Sait's "tamam"; this plan ends at a local preview with before/after screenshots.
- `old-site/` disappears at the end (its files move, nothing is deleted; `git log` keeps the live copy and `main` still holds the deployed tree).

## Review Focus

1. A relative link inside a page (`mac.html`, `guides/`, `../index.html`, `assets/x.webp`, `download_button.svg`) must resolve from a locale folder (`/tr/`) exactly as it does from the root; the link checker proves every target exists.
2. `redesign.js` fetches `pricing.json` relative to the page, which is `/tr/pricing.json` on a locale home: it must fetch `/pricing.json`.
3. A page whose `<main>` wraps the `footer-slot` (the live `index.html`) must not render the sitelinks twice.
4. The hreflang set must list only the locales where that page exists (tr and de have only the home page today).
5. A page-specific body script (`stations.html` has the directory search) must survive the extraction.
