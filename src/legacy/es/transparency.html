Cómo está hecha Macdio.

Macdio es un proyecto de una sola persona. Aquí tienes una mirada honesta a cómo funciona la app, qué datos toca y qué hace falta para construirla.

Quién hace Macdio

Macdio es un proyecto de un solo desarrollador, Sait Firat NEMIS. No hay ninguna empresa detrás, ni equipo, ni inversores. Solo una persona construyendo la app de radio que echaba en falta en el App Store.

Me encargo del código SwiftUI en las seis plataformas, de la web, de la presencia en el App Store y del buzón de soporte. Si escribes a support@macdio.app, me llega directamente a mí.

Cómo está hecha

Macdio es 100 % Swift y SwiftUI nativos. Sin Electron, sin React Native, sin vistas web. Cada pantalla está escrita específicamente para la plataforma en la que se ejecuta: iPhone, iPad, Mac, Apple TV, Apple Watch y CarPlay.

Como la mayoría de los desarrolladores en 2026, uso herramientas modernas asistidas por IA como parte de mi trabajo, para explorar casos límite, prototipar ideas y salir de sesiones de depuración complicadas. Pero la arquitectura central, las decisiones de diseño, el ajuste de rendimiento y el código final que se publica salen de investigación deliberada e iteración a mano. Me importa que los detalles estén bien, y eso significa entender cada capa de la pila en lugar de aceptar lo que genere una herramienta.

Fuentes de datos y API

Macdio no elabora un catálogo de emisoras propio. Las listas de emisoras vienen de Radio Browser, una base de datos pública mantenida por la comunidad, y la copia que Macdio guarda de ella (dir.macdio.app) solo se usa cuando Radio Browser no responde. Los metadatos de lo que suena y las letras vienen de API públicas. Esto es con lo que habla la app:

Radio Browser

Base de datos de emisoras de radio por internet mantenida por la comunidad. Proporciona los metadatos de las emisoras, las URL de los streams, el país y las etiquetas de género. De aquí sale el catálogo de decenas de miles de emisoras.

radio-browser.info ↗

API de búsqueda de iTunes

La API de búsqueda pública de Apple, usada para enriquecer la información de lo que suena obteniendo la carátula del álbum, el año de publicación y el nombre del álbum a partir de los metadatos de pista que emiten las emisoras.

API de búsqueda de iTunes ↗

LRCLIB

API de letras gratuita y de código abierto. Proporciona letras sincronizadas (formato LRC) y en texto plano para la canción que está sonando. Sin clave de API, sin rastreo.

lrclib.net ↗

Podcast Index

Índice abierto e independiente de 4,7 millones de podcasts. Hace funcionar la búsqueda, las listas de éxitos y las categorías de podcasts. Los episodios y los feeds se descargan después directamente del servidor de cada programa.

podcastindex.org ↗

Apple ShazamKit

El reconocimiento de canciones de Apple. Song ID envía una breve firma de audio del stream, nunca una grabación y nunca el micrófono, y recibe la canción, el artista y la carátula.

ShazamKit ↗

push.macdio.app

El propio servidor de notificaciones de Macdio para los episodios nuevos. Solo cuando activas las notificaciones recibe la dirección de notificaciones del dispositivo y los programas que sigues, y nada más.

Política de privacidad

Dependencias

Macdio tiene una huella de dependencias mínima. La propia app usa cero paquetes Swift de terceros. Está construida por completo con los frameworks de Apple (SwiftUI, SwiftData, AVFoundation, CloudKit, MediaPlayer).

Esta web es igual de ligera. No carga fuentes web ni bibliotecas 3D. La tipografía usa la fuente del sistema que ya tiene tu dispositivo Apple, y cada animación es CSS y JavaScript sin más. Los servicios externos son:
