Transparence

Comment Macdio est conçu.

Macdio est un projet solo. Voici un regard honnête sur le fonctionnement de l'app, les données qu'elle touche et ce qu'il faut pour la construire.

Qui développe Macdio

Macdio est le projet d'un développeur solo, Sait Firat NEMIS. Pas de société derrière, pas d'équipe, pas d'investisseurs. Juste une personne qui construit l'app de radio qui semblait manquer sur l'App Store.

Je m'occupe du code SwiftUI sur les six plateformes, du site web, de la présence sur l'App Store et de la boîte d'assistance. Si vous écrivez à support@devdio.pro, c'est moi que vous joignez directement.

Comment il est conçu

Macdio est 100 % natif, en Swift et SwiftUI. Pas d'Electron, pas de React Native, pas de vues web. Chaque écran est écrit spécifiquement pour la plateforme sur laquelle il tourne : iPhone, iPad, Mac, Apple TV, Apple Watch et CarPlay.

Comme la plupart des développeurs en 2026, j'utilise des outils modernes assistés par IA dans mon travail, pour explorer des cas limites, prototyper des idées et me sortir de séances de débogage épineuses. Mais l'architecture de fond, les choix de conception, le réglage des performances et le code final livré viennent tous d'une recherche délibérée et d'itérations à la main. Je tiens à ce que les détails soient justes, et cela veut dire comprendre chaque couche de la pile plutôt que d'accepter ce qu'un outil génère.

Sources de données & API

Macdio ne compose pas son propre catalogue de stations. Les listes de stations viennent de Radio Browser, une base de données publique tenue par la communauté, et la copie qu'en garde Macdio (dir.macdio.app) ne sert que lorsque Radio Browser ne répond pas. Les métadonnées de lecture et les paroles viennent d'API publiques. Voici à quoi l'app parle :

Radio Browser

Base de données de stations de radio Internet maintenue par la communauté. Fournit les métadonnées des stations, les URL de flux, le pays et les étiquettes de genre. C'est de là que vient le catalogue de dizaines de milliers de stations.

radio-browser.info ↗

iTunes Search API

L'API de recherche publique d'Apple, utilisée pour enrichir les informations de lecture en récupérant la pochette, l'année de sortie et le nom de l'album à partir des métadonnées de titre que diffusent les stations de radio.

iTunes Search API ↗

LRCLIB

API de paroles libre et gratuite. Fournit les paroles synchronisées (format LRC) et en texte brut pour la chanson en cours. Aucune clé d'API requise, aucun pistage.

lrclib.net ↗

Podcast Index

Index ouvert et indépendant de 4,7 millions de podcasts. C'est lui qui fait tourner la recherche de podcasts, les classements et les catégories. Les épisodes et les flux se téléchargent ensuite directement depuis le serveur de chaque émission.

podcastindex.org ↗

Apple ShazamKit

La reconnaissance musicale d'Apple. Song ID envoie une courte signature audio du flux, jamais un enregistrement et jamais le micro, et reçoit en retour la chanson, l'artiste et la pochette.

ShazamKit ↗

push.macdio.app

Le serveur de notifications de Macdio pour les nouveaux épisodes. Seulement si vous activez les notifications, il reçoit l'adresse de notification de l'appareil et les émissions que vous suivez, et rien d'autre.

Politique de confidentialité

Dépendances

Macdio a une empreinte de dépendances minimale. L'app elle-même n'utilise aucun paquet Swift tiers. Elle est entièrement construite avec les frameworks d'Apple (SwiftUI, SwiftData, AVFoundation, CloudKit, MediaPlayer).

Ce site web est tout aussi léger. Il n'embarque ni police web ni bibliothèque 3D. La typographie utilise la police système déjà présente sur votre appareil Apple, et chaque animation est du simple CSS et JavaScript. Les services externes sont :
